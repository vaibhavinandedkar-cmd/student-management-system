# Configuration

## Overview

The `config` directory contains all configuration files required to initialize and run the Student Management System.

It serves as the central location for application settings, database connectivity, environment variables, and other configurable components. Centralizing configuration improves maintainability, security, and consistency across different environments.

---

# Purpose

The purpose of this directory is to separate configuration from application logic.

Instead of hardcoding values throughout the application, configuration files define how the application behaves in different environments such as Development, Testing, Staging, and Production.

---

# Responsibilities

The configuration layer is responsible for:

- Loading application settings
- Reading environment variables
- Initializing database connections
- Registering Flask extensions
- Managing application secrets
- Managing debug settings
- Defining database connection strings
- Initializing migration support
- Providing reusable configuration objects

# Coding Standards

- Never hardcode credentials.
- Use environment variables for secrets.
- Keep configuration modular.
- Separate development and production settings.
- Document every configuration option.

---

# Best Practices

- Use `.env` for local development.
- Keep secrets outside Git.
- Validate required environment variables.
- Use descriptive configuration names.
- Group related settings together.

---

# Common Mistakes

❌ Hardcoding passwords

❌ Committing API keys

❌ Mixing business logic with configuration

❌ Creating multiple database instances

❌ Initializing Flask extensions multiple times

---

# Do

- Use environment variables
- Keep configuration centralized
- Document every setting
- Separate environments

---

# Don't

- Store secrets in source code
- Duplicate configuration
- Modify configuration during runtime
- Commit `.env` files

---

# Security Considerations

Sensitive information such as:

- Database passwords
- Secret keys
- API tokens
- JWT secrets
- Cloud credentials

must never be stored directly in the source code.

Always use environment variables or a secure secret management solution.
