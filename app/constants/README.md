# Constants

## Overview

The `constants` directory contains all application-wide constant values used throughout the Student Management System.

Constants represent fixed values that should never change during application execution. Centralizing these values improves maintainability, reduces duplication, and prevents hardcoded strings or magic numbers from being scattered throughout the codebase.

---

# Purpose

The purpose of this directory is to define reusable constant values in a single location.

Instead of repeating the same values across multiple files, the application imports constants from this directory.

This approach promotes consistency, readability, and easier maintenance.

---

# Why This Directory Exists

Hardcoding values throughout the application leads to:

- Duplicate values
- Typographical errors
- Difficult maintenance
- Inconsistent behavior

The `constants` directory solves these problems by providing a single source of truth for all fixed values.

---

# Coding Standards

- Use UPPER_CASE for constant names.
- Group related constants into dedicated files.
- Avoid duplicate constant definitions.
- Use descriptive names.
- Keep constants immutable.
- Add comments where the purpose is not obvious.

Example:

```python
DEFAULT_PAGE_SIZE = 20

MAX_LOGIN_ATTEMPTS = 5

ACTIVE_STATUS = "Active"
```

---

# Best Practices

- Keep constants centralized.
- Organize constants by feature or domain.
- Replace hardcoded values with constants.
- Document complex constants.
- Reuse constants throughout the application.

---

# Common Mistakes

❌ Hardcoding strings repeatedly

❌ Defining the same constant in multiple files

❌ Using magic numbers

❌ Modifying constant values at runtime

❌ Mixing business logic with constants

---

# Do

- Keep constants immutable.
- Use meaningful names.
- Group related constants.
- Import constants instead of redefining them.

---

# Don't

- Write business logic here.
- Store configuration values here.
- Store secrets or credentials.
- Create database connections.
- Perform calculations.

---

# Performance Considerations

Constants are loaded once and reused throughout the application's lifecycle, making them efficient and lightweight.

---

# Security Considerations

Do **not** store sensitive information such as:

- Passwords
- API Keys
- Database credentials
- Secret keys
- Tokens

These belong in environment variables or configuration files.
